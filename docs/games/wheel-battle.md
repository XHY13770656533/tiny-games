# 转盘大作战 · 策划案

> 状态：规划中  
> 游戏 id：`wheel-battle`  
> 路由：`/games/wheel-battle`  
> 目标平台：Tiny Games 纯前端（Vite + React + TypeScript + Canvas）

## 游戏名称

**转盘大作战**

英文目录名：`wheel-battle`

一句话卖点：**战前自己组装转盘，战时只在关键窗口按下转动。**

它不是「幸运转盘」的换皮，也不是需要走位的雷霆战机。战场看起来仍是纵向空战，玩法更接近塔防：敌机按波次进攻，玩家战机自动开火、自动锁定，玩家不放置防御塔，只通过转盘做升级和强化。

---

## 游戏目标

玩家在进入战斗前装配好转盘，然后观看并干预一场自动空战：击落敌机积攒能量，能量满一次就获得一次可储存的转动机会。玩家要在合适的时机消耗这些机会，让护甲、维修、特殊炮弹在最需要的窗口生效，并在每一关末尾击败大 Boss。

通关目标：打完 3 关并击败最终 Boss「赤红母舰」。

单局追求：尽可能高的综合评分（击坠、漏敌少、Boss 速杀、剩余生命、剩余转动次数）。

---

## 体验定位

| 维度 | 选择 | 原因 |
| --- | --- | --- |
| 类型 | 自动塔防 + 转盘构筑 | 战场自己推进，玩家的操作是「何时强化」 |
| 难度 | 困难 | Boss 有预报窗口，乱转或囤到死都应受罚 |
| 单局时长 | 6–10 分钟 | 适合 Tiny Games，避免做成关卡编辑器 |
| 操作负担 | 极低 | 战斗中只有「转动」和「暂停」 |
| 随机性 | 有约束的随机 | 扇区大小 = 概率，转动时机 = 技术 |
| 失败惩罚 | 本关重开 | 不回退已解锁扇区类型 |

玩家全程只做两件事：

1. **战斗外**：组装转盘，决定自己的概率。
2. **战斗中**：选择时机转动，决定这一次强化落在哪一段战况上。

不需要走位、瞄准、放置防御塔或手动开火。

与现有游戏的边界：

- 相对 `lucky-wheel`：转盘可组装，奖励作用在自动战场，而不是金币账户。
- 相对 `breakout` / `mirror-flyer`：同属 Canvas 循环，但玩家输入不是位移，而是消耗转动次数。

## 核心玩法

- 操作方式：鼠标 / 触控点击「转动」；键盘 `Space` 也可转动；Canvas 只负责演播战场
- 胜利条件：第 3 关 Boss 生命降至 0
- 失败条件：基地生命降至 0
- 分数规则：击坠分 + Boss 阶段分 + 剩余生命加成 + 少漏敌加成；最高分写入 `localStorage`

### 主循环

```txt
进入游戏前组装转盘（方案锁定）
    → 自动空战开始：敌机按波次进攻，战机自动开火
    → 击落敌机获得能量
    → 能量满 100：获得 1 次转动机会，能量清零并继续蓄力
    → 机会可叠加，玩家自行决定何时按下转动
    → 抽到的扇区立刻改写战场状态
    → 清完波次后迎战 Boss
    → 击败 Boss 解锁新扇区，回到整备，再进入下一关
```

战斗一旦开始，**不能再改扇区种类或大小**。下一关开始前允许重新组装，因为新效果会解锁。

### 玩家的唯一战斗决策：何时转动

转动机会不是「满了就必须转」，而是可以存着。正确时机通常是：

- 下一波即将涌入，需要火力覆盖
- 基地残血，需要维修或护甲
- Boss 预报了高伤害技能，需要护盾、清屏或时缓
- 场上有护盾精英 / 双目标，需要穿甲或散射

错误时机通常是：

- 满血满甲时把维修转掉
- 场上没有敌弹时把清屏转掉
- 波次间隙把短时火力转掉
- 一直囤满 3 次机会，被 Boss 技能直接打死

## 战场规则（自动塔防式空战）

视觉仍用雷霆战机式纵向卷轴：星空、敌机、弹幕、关底 Boss。规则按塔防来，不按射击游戏来。

### 空间与镜头

- 纵向卷轴，背景星空缓慢下移。
- 坐标系归一化到 `0–100`（宽）× `0–100`（高），Canvas 只负责缩放绘制。
- 战场分 3 条航道：左 `x=22`、中 `x=50`、右 `x=78`。敌机沿航道推进，可在航道内小幅摆动，方便阅读。
- 玩家战机固定在画面下方中央 `x=50, y=86`，只做轻微悬停动画，**不能被玩家移动**。
- 底线 `y=92` 是基地防线。敌机越过底线视为漏敌，对基地造成撞击伤害后消失。
- 敌机从 `y < 0` 入场。

### 基地与战机

玩家操控的不是飞机走位，而是这座自动炮台。生命、护甲都挂在基地上。

| 属性 | 初始值 | 说明 |
| --- | --- | --- |
| 生命 | 100 | 归零即失败 |
| 护甲 | 0 / 上限 80 | 先扣护甲再扣生命；护甲不自动回复 |
| 锁定 | 自动 | 优先打最靠近底线的敌机，同距离打血量更高的 |
| 自动炮 | 每 220ms 1 发 | 射向当前锁定目标，伤害 8 |
| 特殊弹仓 | 空 | 由转盘装填，用完回到普通炮 |
| 覆盖 | 中路最稳 | 没有散射 / 导弹时，左右路输出偏低 |

受伤后有 350ms 无敌闪烁，避免同一串弹在单帧内把生命打空。无敌期间火力不停。

### 敌机

三类常规单位，全部由 `logic.ts` 的波次表生成，不在组件里手写刷新：

| 类型 | 生命 | 行为 | 漏敌伤害 | 能量掉落 | 击坠分 |
| --- | --- | --- | --- | --- | --- |
| 侦察机 `scout` | 12 | 单航道下压，偶尔对基地射 1 发 | 10 | 12 | 30 |
| 炮艇 `gunship` | 36 | 进入 y=28 后在航道内悬停射击，打完再推进 | 18 | 22 | 70 |
| 精英机 `elite` | 80 | 带小护盾，扇形 5 发；死亡必掉能量 | 28 | 40 | 150 |

刷新约束：

- 同屏敌机上限 10（Boss 战时上限 6 小兵 + 1 Boss）。
- 子弹同屏上限 80，超出时优先回收已飞出屏幕的敌弹。
- 第 1 关前 12 秒只出中路侦察机，用来教「看能量、等时机、按转动」。

### 碰撞与伤害来源

统一 AABB，但玩家没有位移，伤害来源只有两种：

- 玩家弹 × 敌机 / Boss：扣目标生命，玩家弹消失（穿甲弹除外）。
- 敌弹 × 基地：先扣护甲，再扣生命。
- 敌机越过底线：造成漏敌伤害，该敌机离场。
- 特殊弹「脉冲清屏」不是碰撞，而是范围效果函数。

没有「机体互撞需要躲开」。漏敌就是塔防里的漏怪。

### 能量与转动次数

能量和转动次数分开记账。

| 项目 | 规则 |
| --- | --- |
| 能量上限 | 100，满了立刻兑换，不卡条 |
| 兑换 | 能量每满 100，转动次数 +1，能量清零后继续累积溢出部分 |
| 次数上限 | 3。到 3 后能量仍可积，但满 100 不再加次数，改为 30% 转成分数 |
| 战斗节奏 | 能量满时战场不暂停、不强制转动 |
| 消耗 | 按一次「转动」只消耗 1 次机会 |
| 掉落 | 击毁当下直接入条，不做满地捡道具 |

HUD 始终显示：能量条、当前次数 `0/3`、以及「转动」按钮。次数 ≥ 1 时按钮可点；次数 = 0 时按钮灰掉。

转动动画约 1.1s。这一小段可以冻结算效果、让玩家看清指针，但 **不等待动画就不给攒能量**——动画结束后战场按原节奏继续。不要把整场战斗卡死在「必须先转完才能继续」。

## 转盘系统（本作成员差异点）

### 设计原则

1. **战前决定概率，战时决定时机。** 扇区越大，抽中越稳；按得越准，这发强化越值钱。
2. **战斗中方案锁定。** 不能临时把维修格改成清屏。
3. **全部扇区默认是正面效果。** 没有「空奖」「扣血」格。风险来自「转早了、转晚了、转在错误窗口」。
4. **不能把转盘做成只有一个超大格。** 用数量、单格上下限卡死极端解。
5. **效果要能立刻在战场上被看见。** 护甲出盾、维修出绿十字、特殊弹改弹道。

### 组装规则

组装只发生在战斗外：开局整备，以及每关 Boss 战后、进入下一关前。

| 约束 | 数值 |
| --- | --- |
| 扇区数量 | 最少 4，最多 7 |
| 单格权重 | 8–40 |
| 权重总和 | 必须等于 100 |
| 同类型 | 每种效果最多 1 格 |
| 未解锁效果 | 不可装配 |

操作：

- 从已解锁效果列表「加入扇区」
- 拖动滑杆改大小；实现时推荐：**改当前格，剩余权重按其他格原比例重分配**，保证总和恒为 100
- 提供「平均分配」「恢复推荐方案」两个快捷按钮
- 点「进入战斗」后，本关转盘方案冻结，界面切到战场

推荐初始方案（教程默认）：

| 效果 | 权重 |
| --- | --- |
| 紧急维修 | 28 |
| 装甲镀层 | 24 |
| 速射强化 | 22 |
| 散射弹幕 | 26 |

### 转动表现

- 使用圆锥渐变绘制转盘，配色走战场风（红、青、琥珀），不要复制幸运转盘的金币橙。
- 指针固定在 12 点钟。
- 旋转 3–5 圈后停在目标扇区中心角。
- 结果用一行战报写清数值：「转盘停在「装甲镀层」，护甲 +28。」
- 转盘常驻在战场右侧或下方缩略，不必每次都盖住全屏；次数 ≥ 1 时高亮。

### 效果目录

效果分四类。第一关只解锁生存与基础火力；第 2、3 关 Boss 掉落高阶效果。

#### 生存

| id | 名称 | 解锁 | 效果 | 时长 / 层数 |
| --- | --- | --- | --- | --- |
| `repair` | 紧急维修 | 开局 | 回复 22 生命 | 瞬间 |
| `armor` | 装甲镀层 | 开局 | 获得 28 护甲（可叠加，封顶 80） | 持续到被打掉 |
| `aegis` | 相位护盾 | 第 1 关 Boss | 1.8 秒完全无敌，期间仍可开火 | 1.8s |

#### 火力

| id | 名称 | 解锁 | 效果 | 时长 / 层数 |
| --- | --- | --- | --- | --- |
| `rapid` | 速射强化 | 开局 | 射速间隔改为 110ms | 6.5s |
| `spread` | 散射弹幕 | 开局 | 额外向左右航道各射 1 发，伤害 6 | 7s |
| `pierce` | 穿甲弹 | 第 1 关 Boss | 子弹穿透最多 3 个目标，对 Boss / 护盾额外 +35% | 8 发 |
| `missile` | 追踪导弹 | 第 2 关 Boss | 每 0.9s 自动补 1 枚追踪弹，伤害 16 | 5 枚 |

#### 战术

| id | 名称 | 解锁 | 效果 | 时长 / 层数 |
| --- | --- | --- | --- | --- |
| `overclock` | 过载核心 | 第 2 关 | 伤害 ×1.45，但受到的伤害 +20% | 5.5s |
| `purge` | 清屏脉冲 | 第 2 关 Boss | 清除全部敌弹，并对场上敌机造成 24 伤害 | 瞬间 |
| `time-dilation` | 时缓立场 | 第 3 关开场 | 敌机推进与敌弹速度 ×0.45 | 3.2s |

叠层规则：

- 同类持续效果只刷新时长，不无限叠乘。
- `repair` 在满血时转为 10 护甲，避免「抽到回血等于浪费」。
- `purge` 对 Boss 本体只造成 24 伤害，不能一键秒杀。
- 同时最多保持 3 个持续火力效果；超出时顶掉剩余时间最短的一个。
- 过载的承伤惩罚与相位护盾同时存在时，护盾期间不受伤，过载伤害加成保留。

### 组装策略（给关卡设计用）

玩家应明显感到「不是越大越好」，也不是「有次数就立刻转」：

- 把 `repair` 做到 40，Boss 护盾阶段会缺输出窗口。
- 把 `missile` 做到 40，三路杂兵战不如散射来得稳。
- 第 3 关 Boss 有护盾阶段和激光预报，没有 `pierce` / `purge` / `aegis` 会明显吃力。
- 次数囤满 3 次再进 Boss 是合理策略，但前面漏太多敌，基地会先倒。

不要做隐藏惩罚格。如果后期要加「变数」，优先加「双效果扇区」（例如维修量较低但附带一点护甲），而不是空白格。

## 关卡与 Boss

全作 3 关。每关结构固定为：

```txt
整备转盘（战斗外）→ 进入战斗后方案锁定
→ 波次 A（教学/热身）→ 波次 B（混编）→ 波次 C（三路压迫）→ Boss
```

波次之间不切屏。HUD 会预报下一波：航道、敌种、大约到达时间。Boss 入场前清掉残余小兵，给 1.2 秒预警。

预报是给「何时转动」用的信息，不是让玩家去走位。

### 第 1 关 · 流星航线

- 目标：教会能量兑换次数、次数可存、在波次到来前转动。
- 时长目标：90–110 秒进入 Boss。
- 前半只走中路，后半开始出现左右路，促使玩家理解散射的价值。
- 精英机在波次 C 出现 1 架。

**Boss：铁甲甲虫**

- 生命 720，停在中路前方，不需要玩家绕背。
- 阶段 1（100%–55%）：中路三连射，夹杂少量左右弹。护甲和维修足够撑。
- 阶段 2（55%–0%）：预报 1.5 秒后砸下一波弹雨。这是第一次明确的「现在该转」窗口。
- 挑战点：若把 3 次机会都在小兵阶段花光，弹雨会直接打残基地。
- 击败奖励：解锁 `aegis`、`pierce`。

### 第 2 关 · 裂空峡谷

- 目标：强迫使用三路覆盖，并学会把次数留到双目标阶段。
- 炮艇更多，左右路同时推进，没有散射 / 导弹时漏敌会明显增加。

**Boss：双子无人机**

- 生命：左机 420 + 右机 420，必须都击破。
- 两机分列左右航道，交替开火：一边扇形弹，一边对基地瞄准弹。
- 当其中一架被击破，另一架进入狂暴（射速 +40%，推进更靠前）。
- 挑战点：火力偏科会让残机漏伤爆表；在双机齐在时转散射 / 导弹，比打掉一台再转更划算。
- 击败奖励：解锁 `missile`、`purge`。

### 第 3 关 · 赤红母舰

- 目标：终局考试。杂兵少但准，精英机带护盾。
- 开场即解锁 `time-dilation`，并强制回到整备界面重装转盘。

**Boss：赤红母舰**

- 生命 1600，三阶段，具有真实威胁。每个阶段都有可读的预报，而不是靠手速躲开。

| 阶段 | 生命区间 | 机制 | 建议窗口 |
| --- | --- | --- | --- |
| 装甲甲板 | 100%–70% | 正面护盾吸收 50% 普通弹伤害 | 开阶段立刻转穿甲 / 过载 |
| 弹幕核心 | 70%–35% | 预报 2 秒后环形弹 + 追踪弹 | 预报出现时转护盾 / 清屏 / 时缓 |
| 过载核心 | 35%–0% | 召唤 2 架精英护卫，激光扫射前有 1.2 秒充能条 | 充能条亮起再转，不要提前把无敌交掉 |

失败常见原因应可被「方案 + 时机」对策：

- 被弹幕或激光打穿 → 次数留得够，且轮盘里有 `aegis` / `purge` / `time-dilation`
- 打不穿护盾 → 战前装了 `pierce` / `overclock`，并在甲板阶段就转
- 残血却把维修浪费在满血波次 → 次数管理失败
- 左右路漏敌太多 → 战前散射 / 导弹权重不够

击败后进入通关结算，不循环无尽模式（可在后续版本加无尽）。

## UI 结构

复用 `GameLayout`：返回首页、标题、说明、重新开始。游戏内部再分三块。

### 游戏舞台

1. **整备面板（战斗外）**：左侧效果图鉴，右侧转盘预览与滑杆，底部「进入战斗」。
2. **战场 Canvas**：固定战机、三航道敌机、子弹、Boss、背景。提供 `aria-label="转盘大作战战场"`，并用旁路文本同步生命、能量、转动次数、关卡。
3. **HUD**：生命、护甲、能量、转动次数 `n/3`、当前关卡、击坠分、进行中的效果标签、下一波 / Boss 技能预报。
4. **转盘模块（战斗中常驻）**：缩小的转盘 + 「转动」大按钮。次数 ≥ 1 时高亮。按下后播放旋转，不打开新的组装界面。
5. **结算面板**：胜利或失败，展示分数、最高分、转动次数使用记录、漏敌数。

### 操作按钮

- 进入战斗 / 下一关整备
- 转动转盘（次数 ≥ 1）
- 加入 / 移除扇区（仅整备）
- 平均分配、推荐方案（仅整备）
- 暂停（战斗中，打开后冻结循环）

## 逻辑函数建议

全部放进 `src/games/wheel-battle/logic.ts`，组件只负责输入、rAF 和绘制。

- `createInitialState()`
- `createDefaultWheel()`
- `normalizeWheel(sectors)`：纠正 4–7 格、8–40 权重、总和 100
- `resizeSector(sectors, id, nextWeight)`
- `addSector(sectors, id)` / `removeSector(sectors, id)`
- `unlockSectors(state, ids)`
- `lockWheelAndStartLevel(state, levelIndex)`
- `tick(state, dtMs, input)`：主循环，按 phase 分流
- `autoTarget(state)`
- `autoFire(state, dtMs)`
- `spawnWave(state)`
- `tickEnemies(state, dtMs)`
- `tickBoss(state, dtMs)`
- `tickTelegraphs(state, dtMs)`
- `tickBullets(state, dtMs)`
- `resolveCollisions(state)`
- `resolveLeak(state, enemy)`
- `grantEnergy(state, amount)`：满 100 兑换次数，处理 3 次上限
- `canSpin(state)`
- `beginSpin(state)`：次数 ≥ 1 才能进入 `spinning`
- `finishSpin(state, random)`：按权重抽扇区并 `applySectorEffect`
- `applySectorEffect(state, id)`
- `tickEffects(state, dtMs)`
- `checkDefeat(state)` / `checkLevelClear(state)`
- `scoreKill(type)` / `scoreBossPhase(phase)` / `scoreLeakPenalty(type)`
- `buildWheelGradient(sectors)`
- `getSegmentCenterAngle(sectors, id)`

随机数从函数参数注入 `random = Math.random`，方便测试转盘权重。

不要实现 `movePlayer()`。

## 分数与存储

```txt
tiny-games:wheel-battle:high-score
```

计分：

- 侦察机 30 / 炮艇 70 / 精英 150
- 漏敌：侦察机 -15 / 炮艇 -35 / 精英 -70
- Boss 阶段转换 +400，击破 Boss +1200 / +1600 / +2200（按关卡）
- 剩余 1 点生命 +2 分（结算时一次性）
- 结算时每剩 1 次未用转动机会 +80 分
- 能量在次数已满时溢出：多余能量 × 0.3

最高分只在胜利或失败结算时回写，避免战斗中频繁写存储。

## 视觉与音频范围

第一版只做视觉，不上音效库依赖。

- 战场：深蓝到墨紫渐变、星点视差、三条浅色航道。
- 敌机用几何色块：三角侦察机、梯形炮艇、菱形精英。
- 玩家机：青白三角，固定在底部中央，开火时枪口亮片。
- 护甲存在时机体描边变金。
- 无敌：透明度闪烁。
- 预报：Boss / 波次用顶部横条倒计时，不要只靠颜色。
- 转盘：厚描边 + 扇区文字，主色 `#dc2626`。
- Boss：明显大于精英，带生命条。

无障碍：

- Canvas 旁必须有文字状态，包括转动次数和下一次预报。
- 转动结果用 `aria-live="polite"` 播报。
- 颜色不只靠红绿区分效果，要有文字标签。

## 技术约束

- 页面外壳必须用 `GameLayout`。
- 样式用 CSS Modules；共享色变量放 `src/styles/variables.css`。
- 战场用 Canvas，HUD / 转盘 / 整备用 DOM，避免在 Canvas 里画复杂表单。
- `requestAnimationFrame`、键盘监听在卸载时释放。
- 不引入物理引擎、状态库、音频库。
- 不和 `lucky-wheel` 共用 logic，避免两套转盘语义缠在一起。可复用的只有「权重抽取 + conic-gradient」思路。

建议文件：

```txt
src/games/wheel-battle/
├── index.tsx              # 阶段编排、输入、Canvas 绘制
├── logic.ts               # 纯规则与 tick
├── styles.module.css
└── （可选）render.ts      # 若绘制函数过长再拆
```

## 验收标准

### 策划闭环

- [ ] 可以组装 4–7 个扇区，并调整大小，总和恒为 100
- [ ] 点「进入战斗」后不能再改转盘

- [ ] 玩家可在任意有次数的时机转动，结果立刻改变护甲 / 生命 / 武器 / 弹幕
- [ ] 波次和 Boss 技能有预报，作为转动窗口
- [ ] 每关末尾有独立机制的 Boss，第 3 关 Boss 分阶段且具威胁

## 实现分期

只做策划时不要一次写完整战斗。建议实现按四个可玩切片交付：

1. **整备 + 转盘原型**：能组装、能转、能看到效果文本。进入战斗后方案锁定。
2. **自动空战沙盒**：固定战机、三航道敌机、自动锁定开火、能量条、漏敌扣血。没有走位。
3. **次数叠加接转盘**：满能量 +1 次机会，可存到 3；玩家选时机转动，效果改射速 / 护甲 / 生命。
4. **三关 Boss**：铁甲甲虫 → 双子无人机 → 赤红母舰，全部带预报窗口，补结算与最高分。

每一片都应能独立打开页面玩，而不是最后才拼起来。
